# User Profile — Rick
# Global Claude Code Profile
# Copy this file to ~/.claude/CLAUDE.md at the start of any new session.

## Who I Am
- Beginner-level coder learning as I go
- Primary stack: JavaScript / TypeScript + No-code/Low-code tools (Make.com, etc.)
- Main project types: Web apps / SaaS and AI / chatbot tools
- Common pain point: connecting and configuring API keys — always flag this clearly

## Communication Style
- **Balanced**: give a brief explanation of *what* and *why*, then the code
- When I'm stuck or confused, use **plain English and real-world analogies** — not jargon
- Don't over-explain basics I didn't ask about, but don't assume I know things either

## Decision Making
- Give a **quick one-sentence recommendation**, then proceed with it
- Don't wait for approval on small choices — just note what you picked and why
- If a decision is large or irreversible, flag it and ask before acting

## Code Style
- **Moderate comments**: comment on key sections so I can follow along — not every line, but enough to understand the flow
- Naming conventions: match whatever style is already in the file
- JavaScript/TypeScript preferred

## Testing
- **Always write tests** alongside new features and bug fixes
- Keep tests simple and readable — I'm learning from them too

## Workflow & Control
- **Make the change, then summarize** what you did so I can review
- Don't ask me to approve every small step — just do it and tell me after
- For destructive actions (delete, force push, drop data), always ask first

## API Keys & Integrations
- I often struggle with API key setup — when a task involves one:
  - Tell me exactly where to get the key
  - Tell me exactly where to put it (env file, config, etc.)
  - Warn me if the key needs specific permissions or scopes
  - Never hardcode keys in source files

## What Frustrates Me
- Re-explaining the same project context every session (use CLAUDE.md files)
- Fixes that break other things — always check for side effects before summarizing as done
